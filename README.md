# Steel Control — בוט וואטסאפ (גרסה 2)

הבוט מקבל הודעות וואטסאפ דרך Twilio וכותב אותן ישירות למערכת Steel Control.

---

## למה הגרסה הישנה הפסיקה לעבוד

1. **ה-RLS נסגר.** קודם כל אחד עם המפתח הציבורי יכול היה לכתוב למסד. עכשיו נדרש
   משתמש מחובר ומאושר, ולכן כל בקשה של הבוט הישן נדחית.
2. **הסכימה השתנתה.** `due_date` הפך לתאריך אמיתי (המחרוזת הריקה שהבוט שלח נכשלת),
   `reminder_date`/`reminder_time` הוחלפו ב-`reminder_at`, ו-`files` הפך ל-jsonb.

## מה תוקן ומה נוסף

* הבוט מתחבר לסופאבייס **כמשתמש אמיתי** (`בוט-וואטסאפ`, תפקיד «מנהל») ועובר דרך
  ה-RLS כמו כל משתמש. אין צורך במפתח `service_role`.
* **אימות חתימת טוויליו** — בקשה שלא נחתמה על ידי טוויליו נדחית ב-403.
  קודם כל מי שידע את הכתובת יכול היה לכתוב למסד או לשאוב ממנו נתונים.
* **רשימת מספרים מורשים** (`ALLOWED_NUMBERS`) — רק הצוות יכול לכתוב.
* **כל הסודות עברו למשתני סביבה.** הטוקן של טוויליו היה כתוב בקוד.
* **תמונות מהשטח נשמרות** — צרף תמונה להודעה והיא תעלה לאחסון של הפרויקט
  ותופיע בכרטיס המשימה באפליקציה.
* כל הערה חדשה מייצרת **התראה בתוך האפליקציה** לכל הצוות.
* שגיאות מדווחות אמיתית במקום להיבלע, ופקודת «סגור» מבקשת הבהרה כשיש כמה התאמות.

## התקנה

### 1. רוטציה לטוקן של טוויליו — לפני הכול

הטוקן הישן היה כתוב בקוד המקור ולכן יש להתייחס אליו כאל חשוף:
Twilio Console → Account → API keys & tokens → Auth Token → **Rotate**.

### 2. פריסה ב-Render (חינם)

New → Web Service → העלאת התיקייה או חיבור ל-GitHub

* Build Command: `npm install`
* Start Command: `node server.js`

### 3. משתני סביבה ב-Render

| משתנה | ערך |
|---|---|
| `TWILIO_ACCOUNT_SID` | ה-SID מהקונסולה |
| `TWILIO_AUTH_TOKEN` | הטוקן **החדש** אחרי הרוטציה |
| `TWILIO_WHATSAPP_FROM` | `whatsapp:+14155238886` (מספר הסנדבוקס) |
| `SUPABASE_URL` | `https://wgnxokqtysahkceyysjm.supabase.co` |
| `SUPABASE_ANON_KEY` | המפתח ה-publishable |
| `BOT_USERNAME` | `בוט-וואטסאפ` |
| `BOT_PASSWORD` | הסיסמה של חשבון הבוט |
| `ALLOWED_NUMBERS` | המספרים של הצוות, מופרדים בפסיק, בפורמט `+9725…` |
| `PUBLIC_URL` | הכתובת של השירות ב-Render |

`PUBLIC_URL` חייב להיות מדויק — אימות החתימה של טוויליו מחשב את הכתובת המלאה,
וכתובת שגויה תגרום לדחיית כל ההודעות ב-403.

### 4. חיבור לטוויליו

Messaging → Try it out → Send a WhatsApp message → Sandbox Settings →
בשדה *When a message comes in*: `https://<השירות-שלך>.onrender.com/webhook`

### 5. בדיקה

פתח בדפדפן `https://<השירות-שלך>.onrender.com/health` —
תשובה `{"ok":true,"bot":"בוט וואטסאפ"}` אומרת שההתחברות לסופאבייס תקינה.

## שתי הערות תפעוליות

* **התוכנית החינמית של Render מרדימה את השירות** אחרי כ-15 דקות ללא תנועה,
  וההתעוררות לוקחת עד דקה. ההודעה הראשונה אחרי הפסקה ארוכה עלולה לקבל תשובה
  באיחור או לא לקבל כלל. פתרון: לשדרג לתוכנית בתשלום, או להגדיר ping חיצוני
  ל-`/health` כל 10 דקות.
* **סנדבוקס וואטסאפ של טוויליו** דורש שכל משתמש ישלח `join <code>` פעם ביממה־ות
  ומגביל את ההודעות. למעבר לשימוש קבוע נדרש מספר WhatsApp Business מאושר.

## שיוך אוטומטי (גרסה 3)

הבוט אינו מחליט לבד לאן הודעה שייכת. הוא שולח אותה ל-Edge Function
`bot-route` בסופאבייס, שם קוראים את חוקי השיוך שהוגדרו במסך
**משימות → 🤖 בוט וואטסאפ — חוקי שיוך**, מצרפים את הכרטיסים הפתוחים,
ושולחים לקלוד. המפתח של קלוד יושב ב-Supabase ולא כאן.

* קלוד בוחר **מתוך רשימת הכרטיסים שנשלחה אליו** ואינו יכול להמציא כרטיס.
* אם הוא לא בטוח — ההודעה נכנסת כמשימה «ממתין לשיוך» ומופיעה בראש
  מסך המשימות עם בורר יעד. שום הודעה לא הולכת לאיבוד.
* כשל ב-Edge Function גם הוא מסתיים ב«ממתין לשיוך», לא בהודעה שנעלמה.
* כל החלטה נרשמת ב-`bot_log` עם הנימוק — כדי שאפשר יהיה לענות
  על «למה זה נחת שם».

חשבון הבוט (`בוט-וואטסאפ`) קיבל הרשאת קריאה למסכים
planning / production / installation / pricing / billing — בלי זה RLS
מחזיר רשימת כרטיסים ריקה וכל הודעה נופלת ל«ממתין לשיוך».

אין יותר פורמט חובה. אפשר לכתוב «הגיעו הפרופילים לדוניץ» והבוט ימצא
את הכרטיס. הפקודות `סיכום`, `מה פתוח`, `סגור` ו`עזרה` עובדות כרגיל.
